# Storage Layouts and Bindings

The `internal/store` package decides where a wiki lives and owns every
non-page state file. No other package computes wiki paths itself: commands
resolve a `store.Layout` once and pass it down. `internal/ignore` supplies the
`.openwikiignore` matcher that every source-reading component applies.

## Layouts

A `Layout` names one repository root and one wiki root, and derives every
control path from the wiki root: `.claims/`, `.run.json`,
`.page-manifest.json`, `.last-update.json`, and `INSTRUCTIONS.md`.

| Kind | Wiki root | Writes into the repository |
| --- | --- | --- |
| `in-repo` | `<repo>/openwiki` | yes (the wiki itself, optionally an `AGENTS.md` block) |
| `external` | `$XDG_DATA_HOME/owcli/wikis/<id>/openwiki` | nothing |

The external layout exists for exploring projects you do not own. Its `<id>`
is a readable slug of the repository directory name plus the first 12 hex
digits of the SHA-256 of the canonical repository root, so two checkouts with
the same name never collide. Both layouts name the wiki directory `openwiki`,
so page identifiers are always `/openwiki/<path>.md`, matching upstream
manifests. `RepoExclusions` reports `openwiki` in both layouts: a repository
explored externally may carry its own upstream-generated `openwiki/` folder,
and that folder is never treated as source.

## Binding and resolution

`Dirs` locates owcli's own state: `$XDG_CONFIG_HOME/owcli/bindings.json` (the
registry) and `$XDG_DATA_HOME/owcli` (external wikis), with the usual
`~/.config` and `~/.local/share` fallbacks. Repository roots come from
`git rev-parse --show-toplevel` with symlinks resolved, so a repository must
be a Git work tree.

`Resolve` picks the layout for the repository containing a directory:

1. an explicit registry entry wins;
2. otherwise an existing `<repo>/openwiki` directory is an implicit in-repo
   binding (this is how wikis generated by upstream OpenWiki are picked up);
3. otherwise the repository is unbound (`ErrUnbound`).

`Bind` is idempotent for the same kind but refuses to switch kinds; the user
must `owcli unbind` first, so no wiki is silently orphaned. An external bind
creates the wiki directory under the data directory. `Unbind --purge` deletes
an external wiki but refuses to delete an in-repo one, since that belongs to
the repository and should be removed with Git.

`owcli init` binds an unbound repository implicitly: in-repo by default,
external with `--external`. `owcli update` and the read-only commands require
an existing binding.

## State files and atomic persistence

All JSON state goes through `WriteJSONAtomic`: data is written to a fresh
temporary file in the target directory, synced, and renamed over the target,
so a crash leaves either the old or the new content. Output is two-space
indented without HTML escaping, which keeps code in Claim statements readable.

`ReadJSON` distinguishes three outcomes: missing (not an error), valid, and
present-but-untrustworthy (`ErrInvalidState`), which callers surface rather
than discard. Unknown fields are tolerated so state written by upstream or a
newer owcli still loads.

| File | Schema | Notes |
| --- | --- | --- |
| `.page-manifest.json` | `schemaVersion` 1, `pages` keyed by page id | `pageVersion` (hash of the page bytes), `completedBy`, `completedRunId`, `gitHead`, `sourceFingerprint`; same field names as upstream |
| `.last-update.json` | `updatedAt`, `command`, `gitHead`, `model`, `status`, `language` | a record without `status` predates that field and counts as `complete` |
| `.run.json` | owned by `internal/run` | see [Generation Run Lifecycle](../workflows/generation-run.md) |
| `.claims/<page>.json` | owned by `internal/claims` | see [Grounded Claims](../concepts/grounded-claims.md) |

## `.openwikiignore`

The matcher reads `.openwikiignore` from the repository root with
gitignore-like rules: blank lines and `#` comments are skipped, the last
matching rule wins so `!pattern` can re-include, a leading or inner `/`
anchors to the root, a trailing `/` makes a rule directory-only, `*` stays
within a segment, `**` spans segments, and matching is case-insensitive. One
deliberate difference from upstream: a directory-only pattern does not match
a *file* of the same name in a subdirectory.

`.git` is a fixed exclusion, and `Exclude` adds more (the wiki directory).
Fixed exclusions cannot be undone by a negated rule. `SkipDir` tells walkers
when pruning a directory is safe, which is only when no negated rule could
re-include something below it.

The same matcher gates agent reads, evidence resolution, and the source
fingerprint, so an ignored file can neither be read by a model, cited as
evidence, nor trigger an update.
